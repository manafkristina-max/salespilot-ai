## Анализ Harvey и способ интеграции

Harvey (Python 3.11+, FastAPI, aiosqlite) — автономный агент с heartbeat-циклом каждые 15 минут, моделью через Claude Code CLI-подписку, отправкой через Gmail/Microsoft/SMTP/Instantly и собственным dashboard на vanilla JS.

| Компонент Harvey | Решение | Почему |
|---|---|---|
| `integrations/tech_detect.py` | **Переиспользован** | Фингерпринты стека без сетевых запросов → фактор «технологическая совместимость» |
| `public_http.py` | **Переиспользован** | SSRF-защита (проверка IP, DNS rebinding) для live-исследования и проверки фактов |
| `untrusted.py` (`fence`, `UNTRUSTED_RULE`) | **Переиспользован** | Защита от prompt-injection в данных сайтов при live-LLM |
| `gate.py` (`do_not_contact_*`) | **Переиспользован** | Корректное сопоставление DNC по адресу и домену с границей метки |
| `fit.py` | **Идея адаптирована** | «Одно число + причины» расширено до 5 настраиваемых факторов, неопределённости и стоп-критериев |
| `main.py` heartbeat, `brain.py`, `claude_runtime.py` | Не используется | Бесконечный цикл и зависимость от Claude CLI-подписки противоречат требованиям MVP |
| Gmail / Microsoft / Instantly / LinkedIn / discover | Не используется | Нужны внешние доступы; LinkedIn/скрейпинг поисковиков — ToS-риски |
| `dashboard.py` + `web/` | Не используется | Требовался продукт уровня B2B SaaS на React; модель данных другая (кампании, ICP, версии писем) |

Harvey подключён как git submodule в `vendor/harvey` (commit `6b6a23a`) без изменений; `harvey_adapter.py` добавляет его в `sys.path` и импортирует только модули без тяжёлых зависимостей (playwright, dnspython не нужны). Если каталога нет, адаптер включает консервативные fallback-реализации, а в Настройках интеграция Harvey показывается как ошибка.

## Мультиагентная система

Агенты — детерминированные функции сервиса с общим контрактом: вход (лид/компания + настройки), выход (данные в БД), запись в `agent_runs` (статус success/error/skipped, провайдер, сообщение, длительность). Оркестрация — последовательный конвейер `run_pipeline` по кнопке, без фонового цикла.

| Агент | Вход → выход | Провайдер (Demo / Live) |
|---|---|---|
| **Агент поиска** | ICP → компании + лиды кампании | Демо-датасет · CSV · вручную / live-поиск **не подключён** (возвращает явную ошибку) |
| **Агент-исследователь** | компания → факты с `source_url`, `evidence`, `checked_at`, стек | Демо-факты (`verification=demo`) / загрузка главной страницы, извлечение сигналов, **без людей и email** |
| **Агент квалификации** | компания + факты + ICP → score 0–100, факторы, уверенность, недостающие данные, стоп-критерии | Правила (одинаково в обоих режимах) |
| **Агент подбора продукта** | факты + каталог продуктов → рекомендованный продукт и обоснование | Правила по ключевым словам болей |
| **Агент-автор писем** | бриф (только факты с источниками) → тема, текст с маркерами `[n]`, список утверждений, предупреждения | Mock-шаблон / Anthropic API (fallback на mock при ошибке) |
| **Агент отправки** | одобренное письмо + подтверждение → `sent` (`live`/`simulated`) | Симуляция / SMTP |
| **Обработчик ответов** | текст ответа → класс (interested / objection / not_interested / unsubscribe / out_of_office / other), уверенность, обоснование; отписка → DNC | Правила; ответы вводятся вручную (почтовый ящик не подключён) |

### Скоринг

`score = Σ (weight_i / Σweight) × 100 × value_i`, где `value_i ∈ [0,1]`; фактор без данных засчитывается как 0.3 (отсутствие данных не может завысить оценку). `confidence` = доля веса, опирающаяся на реальные данные. Квалификация: `score ≥ threshold` **и** `confidence ≥ 0.6` **и** нет стоп-критериев (отрасль/география вне ICP). Компания из DNC → 0.

### Жизненный цикл письма

```
draft ──submit──▶ needs_review ──approve──▶ approved ──send(confirm)──▶ sent (live|simulated)
  │                    │                        │
  └──────reject────────┴──────────reject────────┘──▶ rejected ──reopen──▶ draft
правка approved ⇒ needs_review (одобрение снимается); правка sent запрещена
```

Каждое действие пишется в `email_versions` (версия, тема, текст, статус, автор, примечание).

### Разделение реальных и демо-данных

- `companies.is_demo` — источник истины; демо-факты имеют `verification=demo` и не могут быть отмечены как проверенные.
- `emails.send_mode` = `live` только после реальной SMTP-отправки; ответы на `simulated`-письма считаются демо.
- Аналитика имеет scope `real | demo | all`; в `real` отправки и ответы считаются только `live`.
- ROI, выручка и прогнозы не рассчитываются.

## Безопасность

- Bind только на `127.0.0.1`; ключи только в `.env`, в API/UI не возвращаются.
- Реальная отправка — 9 независимых условий (см. README); `require_manual_approval` заблокирован в коде настроек.
- Защита от header injection в теме/адресе, DNC-проверка, дневной лимит, kill switch «Приостановить все отправки».
- Research не извлекает людей и адреса; контакт нельзя создать без указания источника.
- Live-загрузка сайтов — только через SSRF-безопасный клиент Harvey; зарезервированные домены (`.test`, `example.*`) не запрашиваются.

## Тесты

`backend/tests/test_salespilot.py` (24 теста, in-memory SQLite + TestClient): пайплайн и объяснимость score, идемпотентность поиска и защита от дубликатов, CSV-импорт с ошибками строк, обязательность источников, трассируемость утверждений, редактирование/одобрение/отклонение/история, отправка только после одобрения и подтверждения, невозможность live-отправки для демо даже при полной конфигурации, пауза отправок и блокировка ручного одобрения, классификация ответов и раздельная аналитика, фильтры и CSV-экспорт, сохранение данных между перезапусками, консервативность скоринга, стоп-критерии, различение продуктов при подборе, валидация, каскадное удаление, JSON 404 для неизвестного API, публичный демо-режим (блокировка настроек и интеграций, отсутствие утечек ключей), сброс демо-данных.

Дополнительно: `scripts/smoke_test.py` (22 проверки сценария пользователя на запущенном приложении или публичном демо) и `scripts/check_secrets.py` (ключи и `.env` в файлах и всей истории git). Оба запускаются в CI; smoke-тест — внутри собранного Docker-образа.

## Развёртывание

`Dockerfile` (multi-stage: сборка UI на Node 22, Harvey из submodule или с GitHub на закреплённом коммите, Python 3.13 slim, непривилегированный пользователь) и `render.yaml` для Render. Переменная `SALESPILOT_PUBLIC_DEMO=true` принудительно отключает LLM, SMTP и загрузку сайтов, делает настройки read-only и заполняет пустую базу демо-данными при старте. Порт берётся из `PORT`, который задаёт платформа.
